Why this project matters

Every AI tool hands you an answer and expects you to trust it. This one hands you the answer and shows you where it came from — so you can check it in seconds instead of taking it on faith.

The problem it solves

Ask any AI to summarise your notes and you get a clean paragraph with no way to tell where it came from. If it quietly skipped the one line that mattered, or made something up, nothing on the screen tells you. The only way to be sure is to read the whole passage again — which is the exact work you used the tool to avoid.

What this does differently

Every output here is shown beside the exact sentences and words it was built from, strongest first. A sentence scoring 76% is one the answer leaned on. A sentence scoring 2% was ignored. So you verify an answer by glancing at three lines instead of re-reading the page — and if the top-scoring sentence isn't the one you'd have picked, that is your warning.

Where it's actually useful

  • Studying: know whether a summary is safe to revise from before you rely on it.
  • Teaching: see which part of a handout the model latched onto, and which part it walked past.
  • Research: trace a claim back to the paragraph it came from instead of hunting for it.
  • Anything that carries a consequence: medicine, law, finance — fields where "the model said so" is not a reason.

Why it isn't just an AI wrapper

Producing the summary is the easy part — one API call does that. The project is everything around it: cleaning pasted text so citation markers, view counts and headings glued onto sentences don't hijack the result; scoring every sentence against the output that was actually produced; and running two independent explanation methods so that when they disagree, you can see the disagreement rather than being handed one confident number.

It works on more than text

Same question in every format. Images highlight the region the answer was read from. Audio and video transcribe first, then quote the spoken line — with a timestamp and keyframe — sitting behind each part of the answer. A transcript alone tells you what was said; this tells you which part was used.

What it doesn't claim

It shows what an output rests on, not whether that output is true. An answer built on the wrong sentence is still wrong — the difference is that now you can see the wrong sentence. The goal is to make a model's reasoning checkable, not to make it infallible. That's also why the scores aren't rescaled so the best one always reads 100%: a weak match is shown as a weak match.
